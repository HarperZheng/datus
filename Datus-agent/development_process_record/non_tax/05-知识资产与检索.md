# 智能问数知识资产与检索说明

> **定位**：说明"可检索的验证知识"在本项目的三层落地物（存什么、怎么检索、怎么补充），以及把 `development_process_record/non_tax/01~05` 文档接入智能问数检索体系的官方路径。供维护 KB 的人与理解检索机制的人使用。
>
> - 依据链：[01-非税业务说明](01-非税业务说明.md) → [03-宽表选型清单](03-宽表选型清单.md) → [04-非税收入收缴域语义建模与指标标准](04-非税收入收缴域语义建模与指标标准.md) → 本文档。
> - 检索机制一图流：**问数时，agent 先检索下表三类资产，再生成 SQL**——本库验证过的连接键、口径坑、SQL 骨架都在检索范围内，防编造、防扇出、防口径错。

## 一、三层落地物（可检索的验证知识）

| 层 | 落地物 | 存什么 | 落地文件示例路径 | 怎么检索 | 写入机制 |
|---|---|---|---|---|---|
| ① | **语义对象投影**（LanceDB，`semantic_dataset` 投影） | dataset / field / **relationship** 每对象一行——relationship 即"验证过的连接键"知识 | `./subject/semantic_models/yunnan0508/fne_fund_main.yml`（事实源）；`~/.datus/data/yunnan0508/semantic_models/`（LanceDB 投影目录） | `search_semantic_objects(kinds=["dataset","field","relationship"])` 向量检索；raw SQL 生成前命中，**防编造键** | `semantic_modeling` 建模/更新后自动同步（YAML 是事实源，投影是派生物） |
| ② | **knowledge 文件**（`./knowledge/*.md` + `AGENTS.md ## Knowledge` 索引） | 原子业务事实：字段编码、口径坑、必须过滤、扇出陷阱（如 `fentrustno` 扇出 7,070 行、`fab_agen` 直连扇出 4.4 倍） | `./knowledge/non-tax-income.md`（域文件）；`./AGENTS.md`（索引） | 经 `AGENTS.md ## Knowledge` 索引 → `read_file` 按域文件读 | `/init` 初始写入；`extract-knowledge`（lite）持续补充 |
| ③ | **reference_sql**（LanceDB） | 验证过的完整 SQL + 原始问题向量（03 清单的 SQL 骨架是现成候选） | `./subject/sql_summaries/<id>.yaml`（YAML 摘要）+ LanceDB `reference_sql` 向量行 | `search_reference_sql` 语义检索，做 few-shot 示例 | `gen_sql_summary` 逐条沉淀（一条 SQL 一次调用） |

**各层分工一句话**：①管"结构怎么连"（跨表查询的路由依据），②管"为什么这么写"（原子规则，人可直接读），③管"答案长什么样"（few-shot 教例）。

## 二、非结构化文档接入：两条官方路径

### 路径 A（已在用）：文档即文件型知识

`development_process_record/non_tax/01/03/04.md` 本身就是文件型知识——`/init` 生成 `AGENTS.md` 项目地图与索引、`./knowledge/*.md` 原子事实文件，agent 进入会话时经 `<project_context>` 与索引即可读。**轻、零成本、已在生效**。

### 路径 B（重武器，未跑）：`/build-kb` 生成向量资产

`/build-kb` 技能扫描任意文本文件（不限于 md，按内容判断，跳过二进制与超大文件）+ 数据库元数据 → 分类到业务域 → 经 `storage-classify` 路由 → 生成 semantic_models / metrics / reference_sql 向量库 + 挖掘原子知识入 `./knowledge/`。即：**把文档里的验证边、口径规则变成向量可检索资产，运行时被 `search_*` 自动命中**，不再依赖"人记得去翻文档"。
