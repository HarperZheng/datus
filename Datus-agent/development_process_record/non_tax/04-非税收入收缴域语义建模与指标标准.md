## 二、产物与存储

```text
subject/semantic_models/yunnan0508/
├── fne_fund_main.yml        # 资金主链（F1-F7）
├── fne_backpay.yml          # 退付（F8）
├── fne_income_stats.yml     # 收入统计核对（F9-F10）
└── fne_bill_link.yml        # 票据链（B1-B4）
```

- **一个文件 = 一个 semantic model**（一个主题域），内含多个 dataset、relationships、metrics；多张物理表 = 多个 dataset 条目共居一个文件。
- **切分原则**（由 Dosi 三条硬约束推导）：① 有实测验证边相连的连通组**必须同文件**（join 编译单元=文件）；② 无验证边的孤立表**按主题自由成文件**（拆分零损失）；③ 跨表对比指标不依赖同文件——用 query-backed 对比宽表（source_query 预聚合到统一粒度），放任一主题文件；④ 跨链对比（票据↔资金）永远走 raw SQL，不建模硬凑。

### 2.1 文件内部分层结构

每个 YAML 文件内的 dataset 按三层组织：

| 层 | 定义 | 声明 relationship？ |
|---|---|---|
| **核心骨架** | 有实测验证边相连的连通组 | ✅ 骨架内验证边必须声明 |
| **同主题补充** | 无验证边、但主题归属明确的小表，搭车同文件 | ❌ 不声明（无边即不声明） |
| **查询型维度数据表** | `source_query` 去重版维度（`dim_` 前缀），仅当宽表内联字段不够用时启用 | ✅ 与事实表的边需验证 to 侧唯一后声明 |

### 2.4 渐进式加载与扩展规则

- Dosi 递归扫描 `subject/semantic_models/<datasource>/` 按需加载，**上线顺序**：`fne_fund_main` → `fne_bill_link` → `fne_income_stats` → `fne_backpay`；每次 `semantic_modeling` 只编辑一个目标文件。
- **新表接入**：先问"与哪个现有组有验证边"——有→进那个文件；无→新主题新文件。
- 模型文件由 `semantic_modeling` 子代理生成：检视在线 schema → 写 YAML → Dosi 原生校验 → 同步 KB 投影。**禁止手写 YAML 文件**（本文档中的 YAML 仅为目标形态参考）。

## 三、命名标准

| 对象 | 规则 | 示例 |
|---|---|---|
| semantic_model | 小写英文 + 下划线，按业务链命名 | `fne_fund_main`、`fne_bill_link` |
| dataset | 与物理表同名（全小写）；查询型维度数据集用 `dim_` 前缀 | `paybook_full_high`、`dim_agen` |
| field | snake_case 英文业务名，经 expression 映射物理列 | `fill_date` → `toDate(ffilldate)` |
| **metric** | **中文为主**（用户已定），数据源内唯一 | `非税缴款金额_直缴`、`清分金额`、`缴库金额` |
| relationship | 语义化小写 | `cbill_to_paybook` |
| subject_path | 三级：`["非税收入", "资金链"/"票据链"/"统计核对", 业务词]` | `["非税收入","资金链","清分"]` |

> 回退规则：若 Dosi 原生校验拒绝中文 metric name，则改用拼音/英文 name，中文放 `description` + DATUS 扩展（由 `semantic_modeling` 校验裁定）。

## 四、Dataset 定义标准

```yaml
version: 0.2.0.dev0            # 由 semantic_modeling 写入，保留
semantic_model:
  - name: fne_fund_link
    description: 非税收入资金链（缴款→清分→划拨→缴库→退付）
    datasets:
      - name: paybook_full_high
        source: yunnan0508.fne_paybook_full_high   # 必须限定库.表；查询型 dataset 才用 source_query
        description: 缴款书全生命周期宽表（PAYBOOK+ITEM+状态），明细行粒度
        ai_context: 分析缴款/清分/归属/科目层级用；金额可直 SUM，笔数必须 uniqExact(fid)
        fields:
          - name: fill_date
            expression:
              dialects:
                - dialect: CLICKHOUSE        # 与 datasource 方言一致
                  expression: toDate(ffilldate)
            dimension:
              is_time: true
            description: 缴款通知书填开日
            custom_extensions:
              - vendor_name: DATUS
                data: '{"v":"<引擎写入>","time_granularity":"day"}'
        custom_extensions:
          - vendor_name: DATUS
            data: '{"v":"<引擎写入>","time_dimension":"paybook_full_high.fill_date"}'
```

**本库强制规则**：

1. **方言**：所有 expression 用 `dialect: CLICKHOUSE`。
2. **日期转换**：本库日期多为 String，时间字段在 expression 里统一 `toDate(...)`（月表用 `toYYYYMM` 解析或保留 `fmonth` 并标 `time_granularity:"month"`）。
3. **时间字段**：`dimension.is_time: true` + DATUS `time_granularity`（day/month/...）；每个 dataset 的主时间轴写在 dataset 级 `time_dimension`。一个 dataset 只选一个主时间轴（如 full_high 选 `fill_date`；缴库表选 `msg_date`）。
4. **键声明**：`primary_key` / `unique_keys` 只写**实测验证过唯一**的键。`full_high.fid` 有 147 个重复（生命周期多版本）→ **不得声明为唯一键**， fid 作为普通字段并在 ai_context 注明去重口径。
5. **查询型 dataset**：仅当查询结果本身是稳定业务数据集时才用 `source_query`（如"清分宽表非空批次"视图）；否则一律物理表。

## 五、Relationship 定义标准

```yaml
relationships:
  - name: tt_to_funddivide
    from: treasury_transfer_new      # from = 多方（many）
    to: funddivide_transfer          # to   = 一方（one），to_columns 必须是已验证完整键
    from_columns: [ftranscollectid]
    to_columns: [fcollectid]
    custom_extensions:
      - vendor_name: DATUS
        data: '{"v":"<引擎写入>","join_type":"left"}'
```

1. 关系**属于 semantic model**，不属于单个 dataset；且只声明在**核心骨架内部**及**带验证边的同主题补充表**上（对应 §2.1 分层规则）。
2. `from_columns` / `to_columns` 位置一一配对；复合键两侧同序全列。
3. **只有实测验证的连接才可声明**（03 清单 ✅ 项）；❌ 项（如 `fentrustno=fbusinessno` 扇出假关联、跨链 `fpid`、`fcollectpid` 全空）**禁止声明**——这类知识放 dataset 的 `ai_context` 作提示。
4. 声明前需验证 to 侧列唯一性（如 `fab_agen.fagenidcode` 建关系前先 `uniqExact` 核验）。

## 六、Metric 定义标准

```yaml
    metrics:
      - name: 非税缴款金额_直缴
        expression:
          dialects:
            - dialect: CLICKHOUSE
              expression: SUM(paybook_full_high.famt)     # 字段必须带 dataset 限定
        description: 直缴非税缴款金额（缴款通知书明细口径）
        ai_context:
          instructions: 用 fill_date 作业务时间；按执收单位/科目/归属区划分组；与汇缴口径不混算
        custom_extensions:
          - vendor_name: DATUS
            data: '{"v":"<引擎写入>","dataset":"paybook_full_high","time_dimension":"paybook_full_high.fill_date","subject_path":["非税收入","资金链","缴款"],"unit":"元"}'
```

1. `dataset` / `time_dimension` / `subject_path` / `unit` / `window` 等**只放 DATUS `custom_extensions`（JSON 字符串）**，不放在 metric 顶层（原理见 §十：OSI core 封闭字段集 + 扩展槽；省略 vendor_name 静默失效）。
2. 聚合无字段可推断（如 `uniqExact(...)` 之外的 `COUNT(*)`）时，必须显式给 `dataset` 键；聚合白名单与禁令见 §十一。
3. **口径规则写死在 expression**：笔数类一律 `uniqExact(fid)`；时间兜底类用 `coalesce(toDate(fmsgdate), toDate(ftransdate))` 这类表达式；空键过滤与"汇缴/直缴分口径"写入 `ai_context.instructions`。
4. 首批指标清单——**范围：fne_fund_main 全量 16 个（7 基础 + 3 derive + 6 window）+ 其余 3 个文件的起量指标各 1 个**；其余文件的指标扩展不在此列，按 §八 随各模型建模时增量补充（中文命名；归属文件按 §2.2）：

| 指标名 | 表达式（表.字段） | subject_path 三级 | 归属文件 |
|---|---|---|---|
| 非税缴款金额_直缴 | `SUM(paybook_full_high.famt)` | 资金链/缴款 | fne_fund_main |
| 非税缴款笔数_直缴 | `uniqExact(paybook_full_high.fid)` | 资金链/缴款 | fne_fund_main |
| 清分金额 | `SUM(paybook_full_high.fimamt)` | 资金链/清分 | fne_fund_main |
| 划拨金额 | `SUM(funddivide_transfer.ftransamt)` | 资金链/划拨 | fne_fund_main |
| 缴库金额 | `SUM(treasury_transfer_dedup.ftotalamt)` | 资金链/缴库 | fne_fund_main |
| 退付金额 | `SUM(backpay.ftotalamt)` | 资金链/退付 | fne_backpay |
| 票据开票张数 | `uniqExact(cbill_high.fid)` | 票据链/开票 | fne_bill_link |
| 月度收入_统计口径 | `SUM(stats_income_month.ftotalamt)` | 统计核对/月度 | fne_income_stats |

**fne_fund_main 衍生指标（`derive` 扩展键，9 个）**：

| 指标名 | 机制 | 定义 | subject_path |
|---|---|---|---|
| 划拨完成金额 | filter（收窄"划拨金额"） | `fistransfer='1'` | 资金链/划拨 |
| 未划拨金额 | filter（收窄"划拨金额"） | `fistransfer!='1'` | 资金链/划拨 |
| 清分率 | compose（同 dataset 行内计算） | 清分金额 ÷ 非税缴款金额_直缴 | 资金链/清分 |
| 非税缴款金额_直缴_同比 | window | period-over-period，offset 1 年 | 资金链/缴款 |
| 非税缴款金额_直缴_环比 | window | period-over-period，offset 1 月 | 资金链/缴款 |
| 清分金额_同比 | window | period-over-period，offset 1 年 | 资金链/清分 |
| 清分金额_环比 | window | period-over-period，offset 1 月 | 资金链/清分 |
| 缴库金额_同比 | window | period-over-period，offset 1 年 | 资金链/缴库 |
| 缴库金额_环比 | window | period-over-period，offset 1 月 | 资金链/缴库 |

> **窗口指标规则**：每个是独立 metric——OSI 表达式保持纯聚合，比较逻辑写入 DATUS `window` 对象（结构由 `semantic_modeling` 按已装引擎契约生成，不手写）；主时间轴必须是日期类型（`toDate` 转换），查询粒度为运行时参数（month/quarter/year），缺失比较桶保留 null。
> **跨表 compose 禁令**：禁止跨 dataset compose（如"在途资金 = 缴款金额 − 缴库金额"）——M:N 边会使行级 join 后的 SUM 膨胀（测试环境同样错）；跨环节对比用双指标并查（ask_metrics）或二期 query-backed 对比宽表（预聚合到统一粒度后单表做差）。
> **范围说明**：本节首批清单以资金主链（fne_fund_main）为重点，其余 3 个文件（fne_backpay / fne_income_stats / fne_bill_link）各只起 1 个起量指标；退付/统计/票据链的完整指标集（退付笔数、开票金额、同比窗口等）不在首批范围，按 §八 增长回路随各模型建模时增量补充。

## 七、校验与验收标准（每个模型必须全过）

1. **原生校验**：Dosi parser/compiler 通过（semantic_modeling 自动执行）。
2. **投影同步**：`semantic_dataset` 与 `metrics` 投影计数与 YAML 一致。
3. **dry-run**：至少 1 条代表性指标查询编译出 SQL（可用 `query_metrics(dry_run=true)`）。
4. **对账基准**（本库硬数字，指标对不上即拒绝上线）：
   - 清分金额 = 16,016,079,467.68（`funddivide_transfer.fimamt` 全量）
   - 直缴明细 fid 去重数 = 1,101；缴款金额 = 18,332,207,203.13；**缴库金额（去重口径）= 29,535,106.14（76 行；原始 505 行含 462 行冗余，直接 SUM 得 12.94 亿属虚增）**；汇缴 9,012 / 票据 53,386
5. **问数冒烟**：`ask_metrics` 问"2025年8月各州市清分金额"，确认自动命中宽表、时间轴与去重口径。
6. **空缺声明**：对账/记账（F12）、冲红（B8）等无数据环节，指标不得捏造，由 ai_context 声明"数据空缺"。

## 十、OSI core / DATUS 扩展机制补录（源码与词表，来自速查卡）

> 补录来源：`../dosi/dosi_semantic_modeling.md`（含 vendored 规范 `osi-core-0.2.0.dev0.spec.yaml` 通读与 `model.py`/`editing.py` 源码证据）。

### 10.1 分层架构

```
OSI Core Schema（封闭字段集，不允许未知字段，直接放自定义 key 校验失败）
  └─ custom_extensions（OSI 标准预留的厂商扩展槽：vendor_name + data JSON 字符串）
       └─ DATUS entry（vendor_name=="DATUS" 的记录，承载 Datus 特有行为）
```

core 管"是什么"（名、表达式、类型、键、关系），DATUS 管"怎么用"（哪条时间轴、什么粒度、怎么 JOIN、归哪类、什么单位、怎么派生窗口）。不理解 DATUS 的第三方 consumer 忽略该 entry 仍可读取 core model。

### 10.2 运行时寻址：vendor_name 不可省略（源码证据）

引擎读取扩展的统一入口 `datus/tools/semantic_tools/dosi/model.py::datus_payload()` 按 `vendor_name == "DATUS"` **精确过滤**：不匹配即跳过，找不到返回空字典——**省略或拼错不报错，key 全部静默丢失**（time_dimension/window/subject_path/unit 化为无形，模型看似完好但行为退化）。`editing.py` 另规定一个对象最多挂一条 DATUS entry（多条拒绝自动编辑）；`data` 必须是 JSON 字符串（嵌套对象校验失败）。`custom_extensions` 整体 Optional：对象无 Datus 行为时可整个省略（如普通金额字段）。

### 10.3 各层级 DATUS key 速查

| 层级 | key | 说明 | 本项目在用 |
|---|---|---|---|
| dataset | `time_dimension` / `source_type` | 主时间轴（只选一个）/ 查询型标记 | ✅ 三轴三值；✅ `dim_subject`、`treasury_transfer_dedup` |
| field | `time_granularity` / `is_dimension` | 源数据粒度 / 能否作分组维度（false=仅键/表达式引用） | ✅ day；✅ fid/fpid/fsublevel 均 false |
| relationship | `join_type` | `left`/`inner` | ✅ 9 条全 left |
| metric | `dataset` / `time_dimension`（带 dataset 限定）/ `subject_path` / `unit` / `window` / `derive` / `uid` / `format` / `fill_nulls_with` | 归属/时间锚定/检索分类/展示/窗口/派生/稳定身份 | ✅ 16 指标在用 8 种（format、fill_nulls_with 暂未用） |
| semantic_model 顶层 | **无专属 DATUS key** | 行为细节全部下沉到 dataset 及以下 | 顶层不挂扩展（合法） |

完整逐对象 core 字段对照见速查卡 §三（含 `label`、`datatype` 10 值枚举、`dimension.is_time` 默认规则）。

### 10.4 运行时消费方（为什么 key 不能丢）

| 消费方 | 读什么 | 干什么 |
|---|---|---|
| Dosi 编译器 | time_dimension、time_granularity、join_type、window、derive、fill_nulls_with | 时间过滤/上卷、JOIN 类型、窗口展开、派生计算 |
| KB 投影（semantic_dataset / metrics） | subject_path、unit、format、uid | 检索索引；ask_metrics 按 subject_path 命中 |
| 宿主（semantic_modeling） | uid | 稳定身份（24 位 CUID2，引擎写入永不手改），更新/重命名保持不变 |

## 十一、Dosi 引擎执行契约补录（来自 Dosi 建模指南）

> 补录来源：`../dosi/Dosi建模指南.md`（整理自 dosi.datus.ai 官方文档，Dosi 0.1.13 / Ossie 0.2.0.dev0 / Datus 扩展 1.11）。§二"三条硬约束"即下列 1/3/7 条。

### 11.1 聚合表达式契约（§六 的引擎级依据）

- **白名单**：`SUM` / `COUNT` / `COUNT(DISTINCT x)` / `AVG` / `MIN` / `MAX`——指标表达式必须含聚合。
- **禁止**：窗口函数（`window_in_metric`）、子查询、嵌套聚合、`SUM(1)`、多列 `COUNT(DISTINCT a,b)`、引用其他指标（派生走 DATUS `derive` 键）。
- **kind 三分类（引擎自动推断）**：aggregate（单次聚合）/ ratio（两侧裸聚合的除法，自动包 `CAST(numerator AS DOUBLE)` 防整数除法）/ expression（其余；`SUM(a)/NULLIF(SUM(b),0)` 属 expression 型，不会被二次强转）。
- **跨 dataset 禁令**：单次聚合内所有列必须同一数据集（`cross_dataset_aggregate` 错误码）——§九 第 8 条的引擎出处。

### 11.2 JOIN 与路径契约

- 关系只能**多→一**（from=事实表）；沿路径 JOIN 不翻倍行数；路径最长 6 跳；多条路径抵达同一数据集报 `ambiguous_join_path`；自关系与成环不跟进。
- **扇出保护**：SUM/AVG/COUNT 等重复敏感聚合只算在归属数据集上，无安全基时报 `fan_out_risk`——引擎绝不悄悄发出会重复计数的查询（§九 第 8 条"跨边求和膨胀"的机制解释）。

### 11.3 查询侧执行坑（本会话实测）

| # | 坑 | 实证 |
|---|---|---|
| 1 | **中文裸列别名 SYNTAX_ERROR**：ClickHouse 23.3 词法器在多字节首字节断裂（`Unrecognized token: '�'`） | `AS 非税缴款金额_直缴` 报错；`` AS `非税缴款金额_直缴` `` 实测通过；`--` 注释含中文无碍 |
| 2 | **时间范围左闭右开** `[start, end)`，聚合之前编译为 `field >= DATE start AND field < DATE end` | 编译形态见速查卡 §四 |
| 3 | **`LIMIT 1 BY` 不被引擎查询源解析器支持** | 缴库 dataset 的去重规格原文为 `LIMIT 1 BY fid`，已等价改写为 `ROW_NUMBER() OVER (PARTITION BY fid)`（真实 source，L324 起） |
| 4 | **window 扩展结构随版本漂移** | 官方文档 1.2 写 `{type:"pop",offset:"1 month"}`；本库 1.11 写 `{base, offset:{count,granularity,direction}, calculation}`——**一律由 semantic_modeling 按已装引擎契约生成，不手写** |
| 5 | **裸列名必须全模型唯一**（零个 `unknown_column` / 多个 `ambiguous_column`），字段尽量带 dataset 前缀 | metric expression 全部 `dataset.field` 限定的原因 |

### 11.4 与人工标准的衔接

- §七 dry-run 验收 ↔ CLI `dosi query --pretty`（只编译不执行）；`--where` 不允许子查询/窗口函数/内联聚合（应声明为指标再按名引用）。
- §八 bootstrap-kb 批量沉淀路径持续有效；模型词表与契约版本锁定：Ossie 0.2.0.dev0 + DATUS 1.11（引擎/规范升级时 §10.3/§11 须复核）。
- 逐对象字段全表、易混点辨析（`is_time`≠`is_dimension` 等）、运行时链路全景：见 `../dosi/dosi_semantic_modeling.md`。

## 八、持续扩充机制（增长回路）

| 场景 | 动作 | 工具/路径 |
|---|---|---|
| 对话中新口径、新指标需求（日常主路径） | 直接说"把 X 建成模型/加指标" | 主代理 → `task(type="semantic_modeling")`，校验+同步一次完成 |
| 积累了 (问题, SQL) 历史想批量沉淀 | 准备 `question,sql` CSV 批量生成 | `datus-agent bootstrap-kb --components semantic_modeling --success_story <csv> --kb_update_strategy incremental --metrics-batch-size 5` |
| YAML 被手工修改过 | 只重建投影，不跑 LLM 不查库 | `bootstrap-kb --components semantic_model --kb_update_strategy sync-yaml` |
| 想用画像数据刷新字段描述 | 只读画像 + 更新描述 | `--kb_update_strategy refresh-profile --semantic_yaml <yml> --success_story <csv>` |
| 验证过的 SQL 但不值得建指标 | 存 reference_sql | `gen_sql_summary`（经 storage-classify 路由） |
| 业务事实/规则（不属模型） | 存 knowledge | `extract-knowledge`（lite）→ `./knowledge/*.md` |
| 会话偏好、项目决定 | 存 memory | `add_memory` |

**触发节奏**：新表接入、同一口径被反复问、对账发现新坑 → 先更新 03 清单（证据层）→ 再走 semantic_modeling（模型层）。**模型只增不删口径**；废弃指标改名留档，不物理删除。

## 九、禁止事项

1. ❌ 手写 semantic_models / metrics YAML（一律经 `semantic_modeling`）；本文档 YAML 仅为形态参考。
2. ❌ 声明未实测验证的键（unique_keys / relationships / primary_key）。**测试环境放宽规则**：to 侧唯一性可放宽（JOIN 连通性仍须实测），但预期基数必须记入 ai_context 备查，生产化时按 §七 复验升级。
3. ❌ 跨链用 `fpid` 连票据与缴款（唯一连通键 `fpaycode`）；`fid` 跨 `_new`/`_high` 混连。
4. ❌ metric 顶层放 `dataset/time_dimension/subject_path/unit/window`（属 DATUS custom_extensions）。
5. ❌ 一个对象挂多个 DATUS 扩展条目；改动引擎写入的 `v` 版本。
6. ❌ 汇缴（une_）与直缴（fne_）混算；未过滤空键（`fcollectid != ''`）。
7. ❌ 为 0 行表（`fne_treasury_transfer_main` 等）建 dataset。
8. ❌ 跨 dataset 的金额 compose / 跨边求和（M:N join 会使 SUM 膨胀，测试环境同样错）；金额指标一律锚定单 dataset。
