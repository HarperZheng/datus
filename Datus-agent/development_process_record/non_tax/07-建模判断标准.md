
# 建模判断标准（判定准则）

> 本文是全项目所有判定字段建模标准（✔ 建模 / ⏸ 缓建 / ❌ 不建 / 🔜 优先）的统一依据，新增字段时按此五步走：

### 1 五步判定流程

```text
第 1 步 实测   SELECT DISTINCT/GROUP BY 码值 + 填充率 + distinct 数
              （fbustype 事件的教训：未经 distinct 实测的列禁止入模）
第 2 步 定性   该列是【分析口径】还是【过程记录】？
              → 过程记录（流水号/报文字段/审计元数据/账号隐私/多版本冗余/扩展槽）→ ❌ 终止
第 3 步 可解   码值能否赋业务语义？（字典表可查 / 内联 name 列 / 业务方可确认）
              → 有值无义（如 fpaychannel 码 11/13 无字典）→ ⏸ 缓建，先问业务
第 4 步 独源   信息是否已被其他列/其他 dataset 覆盖？
              → 名称列与编码列同义 → 编码让位名称（建 fchgbgtagenname 不建 fchgbgtagencode）
              → 宽表副本 vs 权威底表 → 只建权威源（ftransamt 只建 funddivide_transfer）
              → 可由已建字段推导（年月由日期推导、主键去重后等价）→ ❌/⏸
第 5 步 定级   仍有独立分析价值 → 排优先级入模：
              P0 = 顶级分析维度 / 缺失即答不了某类问题（资金性质、收入分类）
              P1 = 跨链桥键 / 场景定义字段（fpaycode、fsharerate）
              P2 = 二级时间轴 / 低频钻取（clear_date、fisleaf）
```

### 2 ❌ 永不建模白名单（硬排除）

| 类别 | 识别特征 | 本文件实例 |
|---|---|---|
| 事实流水号 | fid/fno/serialno/batchno 中"非分组键"的号段 | ftranobus、ffundsserialno、fprinttransno、ftaskno |
| 报文/凭证参数 | msg、voucher、dictate、print 类 | fmsgbatchno、fmsgid、fvouchercode、fpaydictateno |
| 账号与隐私 | acct(含尾号外全称)、idcode、tel、email、证件、法人、联系人 | ftransrecacct*、fpayacct*、fpayertel、flegalman |
| 系统审计元数据 | oper、author、createtime、updatetime、version、altercode、externalid | foperator、fversion、fupdatetime |
| 多版本冗余 | `_last` 后缀（生命周期中间态） | ftransno_last、fenterdate_last |
| 扩展槽 | fcustom1~N、fcustomN1~N2 | 全部 |
| 实测死列 | distinct∈{0,1} 或全空/全同值 | fdatatag（全空）、ftransstats（funddivide 侧全空）、fisenter（≤1 活跃） |
| 已证不连通键 | 实测 JOIN 0 行的假关联 | fsubid（≠fab_subject.fid）、fcollectpid（全空）、fentrustno（扇出 7070） |
| 数据空缺场景 | 填充率<5% 且对应业务场景本身缺数据 | freconcilestatus 族（F12 空缺）——按 04 标准 §七.6 声明空缺，不建模 |

### 3 ⏸ 缓建条件（满足任一即缓建，并记录解锁条件）

1. **码值无字典**：有值无义（fpaychannel 11/13）→ 解锁条件：业务方确认或 mon_* 字典表命中；
2. **同义冗余**：与已建模列同义（编码↔名称、主键↔业务键）→ 解锁条件：出现"按编码精确对齐外部系统"需求；
3. **可推导**：由已建模字段可计算（fpayyear←pay_date、fisleaf←树遍历）→ 解锁条件：推导性能或正确性出现问题时物化；
4. **低频场景**：对应场景（时效分析、银行渠道、纳税人）暂无问数需求 → 解锁条件：需求出现；
5. **子流程状态**：主状态已建模，子状态暂无消费方（fbillstatus/fenterstatus 族）→ 解锁条件：对应子流程纳入分析。

### 4 🔜 优先建模信号（出现即提升优先级）

1. **事实表新维度 vs 维度表属性交叉**：维度侧字段可反向校验事实侧数据质量——**校验型字段优先建**，但必须先过第 1 步实测（2026-10-20 教训：dim_subject.ffundsnaturecode 校验设想合理，实测源列 3,143 行全空，候选否决并转为数据质量问题）；
2. **跨链唯一桥键**：已实测验证的连通键（fpaycode）→ 下一个建模文件的 join 依赖，必须提前铺；
3. **dataset 缺时间轴**：事实 dataset 无 time_dimension（agen_treasury_high 修复案例）→ 结构性缺陷最高优先；
4. **用户问数失败复盘**：任何一次"语义层答不了、裸 SQL 才能答"的问题，涉及的列自动进入下批候选。

### 5 命名与声明规范（建模时执行）

- 逻辑名用业务语义 snake_case（funds_nature/income_sort/clear_date），物理映射经 CLICKHOUSE expression；
- Date 类物理 String 列必须 `toDate(...)` 包裹；主时间轴在 DATUS `time_dimension` 声明（每 dataset 恰一条），其余时间字段仅作普通可分组字段；
- 分类码值列 description 必须写入 **distinct 实测的码值→含义→行数分布**；同码表跨 dataset 建模时注明"与 XX 同码表"；
- 测试数据污染 >5% 的维度（fpayername）必须在 description/instructions 声明污染比例；
- **键/粒度实测延伸**（2026-10-20 cbill_high 事件）：粒度判定不能停在"这列叫 fid/fpid"，必须实测该列与明细表、主表的双向命中；发现"同名键跨链/跨表语义漂移"（fid≈行键、fpid≈单据键）时，指标的计数口径跟着键走（张数=fpid，行数=fid），并登记 06 台账勘误；
- **工具可信度**（2026-10-20 cbill_high 事件）：`describe_table` 可能返回幽灵列（cbill_high 的 fbusinesstype、paybook_high 的 fisinvoice/fisarriveaccount/fbillname/fbillsource 实测不存在），字段存在性一律以 `system.columns` 查询为准。
