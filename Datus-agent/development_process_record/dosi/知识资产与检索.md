# 知识资产总览：类型、生成方式、作用与存储位置

> **定位**：一张地图回答四个问题——本项目支持哪些知识资产？哪些自动生成、哪些要业务引入？各自作用？存在哪？
> **依据**：2026-10-21 源码核对（datus/storage/*、datus/cli/*、datus/main.py）+ 本机 `.datus/data/` 实测。
> **配套**：[06-当前建模字段清单](06-当前建模字段清单.md)（字段级台账）、[07-建模判断标准](07-建模判断标准.md)（入模判定）。

---

## 一、总览图：知识资产的两大类、八小类

```text
知识资产（AI 问数时检索的一切）
├── A. 向量知识库（KB，LanceDB，机器检索）——"按意思搜"
│   ├── A1 语义对象投影      semantic_dataset.lance   ← 建模自动生成
│   ├── A2 指标投影          metrics.lance            ← 建模自动生成
│   ├── A3 主题树            subject_tree.db          ← 建模自动生成
│   ├── A4 表结构元数据      schema_metadata.lance + schema_value.lance ← bootstrap-kb metadata 组件
│   ├── A5 参考 SQL          reference_sql.lance      ← gen_sql_summary 逐条沉淀（半自动）
│   ├── A6 参考模板          reference_template.lance ← YAML 模板导入（半自动）
│   └── A7 平台文档          document/{platform}/     ← platform-doc 命令导入（业务引入）
└── B. 文件型知识（人类可读，agent 按索引读文件）
    ├── B1 项目地图+知识索引  AGENTS.md               ← /init 生成（半自动）
    ├── B2 原子知识文件       ./knowledge/*.md         ← /init 生成 + extract-knowledge 补充
    ├── B3 建模台账与标准     development_process_record/*.md ← 人工编写（业务引入）
    ├── B4 语义模型源文件     subject/semantic_models/*.yml ← semantic_modeling 生成（KB 的"事实源"）
    └── B5 持久记忆          .datus/memory/<node>/MEMORY.md ← 会话沉淀（自动+人工）
```

**一句话**：A 类入向量库、按语义相似度检索；B 类是纯文件、靠 AGENTS.md 索引或固定路径读取。A 类的"事实源"是 B4 的 YAML——投影只是派生物。

## 二、逐项说明（类型 / 生成方式 / 作用 / 存储位置 / 检索方式）

### A1 语义对象投影 ⭐ 本项目已建

| 项 | 说明 |
|---|---|
| **存什么** | dataset / field / relationship 每对象一行（含描述、表达式、synonyms、连接键）——relationship 即"验证过的连接键"知识 |
| **怎么生成** | ✅ **自动**：`semantic_modeling` 会话收尾时 `sync_osi_to_db` 自动投影；`bootstrap-kb --components semantic_model --kb_update_strategy sync-yaml` 是 YAML 手改后的手动重放（无 LLM、无仓库访问） |
| **作用** | `search_semantic_objects` 语义检索：gen_sql 写 SQL 前命中正确的表/字段/键，**防编造字段名、防假关联**（如 fpaycode 桥键、fentrustno 扇出禁令都随描述入库） |
| **存储位置** | `{datus_home}/data/{project_name}/datus_db/semantic_dataset.lance`<br>本机：`.datus/data/mnt-d-develop-datus-Datus-agent/datus_db/semantic_dataset.lance` |
| **本机现状** | fne_fund_main：7 dataset / 100 字段 / 9 relationship（两批建模自动同步，2026-10-20） |

### A2 指标投影 ⭐ 本项目已建

| 项 | 说明 |
|---|---|
| **存什么** | 指标定义行：名称、类型（aggregate/window/compose/filter）、表达式、subject_path、口径描述 |
| **怎么生成** | ✅ **自动**：与 A1 同一次 `sync_osi_to_db(include_metrics=True)` 双写；A1/A2 不可拆分单独同步 |
| **作用** | `search_metrics` 按业务语义搜指标（搜"直缴金额"→命中 `非税缴款金额`+fbustype 切片提示）；ask_metrics 的第一步 |
| **存储位置** | `…/datus_db/metrics.lance` |
| **本机现状** | 16 个指标（2026-10-20 两批建模后，改名 非税缴款金额/非税缴款笔数 已同步） |

### A3 主题树 ⭐ 本项目已建

| 项 | 说明 |
|---|---|
| **存什么** | 指标/资产的分类层级（如 非税收入→资金链→缴款），随指标 subject_path 自动建节点 |
| **怎么生成** | ✅ **自动**：指标投影时 `find_or_create_path` 顺带创建（subject_path 写在 YAML 指标的 DATUS 扩展里） |
| **作用** | `list_subject_tree` 导航；search 前先看树确定 subject_path；是指标的"目录" |
| **存储位置** | `…/datus_db/subject_tree.db`（sqlite） |
| **本机现状** | 6 节点：非税收入/资金链/缴款·清分·划拨·缴库 |

### A4 表结构元数据 ⚠️ 部分建立

| 项 | 说明 |
|---|---|
| **存什么** | 表/列的物理元数据 + 采样值（schema_metadata.lance + schema_value.lance） |
| **怎么生成** | ✅ **自动**：`bootstrap-kb --components metadata`（默认组件），扫库写入；`schema_linking_type` 控制表/视图/MV 范围 |
| **作用** | `search_table`（按描述搜表）；schema linking 的底料——没它 gen_sql 只能靠 `list_tables` 现查 |
| **存储位置** | `…/datus_db/schema_metadata.lance`、`schema_value.lance` |
| **本机现状** | 已有数据（2026-10-16 初始化），但早于全部建模——**可重跑 incremental 刷新** |

### A5 参考 SQL ⚠️ 未沉淀（候选就绪）

| 项 | 说明 |
|---|---|
| **存什么** | 验证过的完整 SQL + 原始问题向量（few-shot 教例） |
| **怎么生成** | ◐ **半自动**：`gen_sql_summary` 子代理逐条沉淀（一条验证过的 SQL 一次调用）；无批量自动生成 |
| **作用** | `search_reference_sql` 命中历史同类问题的高质量 SQL 做 few-shot，显著提升同类问题一次成对率 |
| **存储位置** | 向量行在 `…/datus_db/reference_sql.lance`（本机未出现）；YAML 摘要在 `subject/sql_summaries/<id>.yaml`（未建立） |
| **候选池** | 03 清单 3 条骨架（资金链聚合/缴库批次/票据↔缴款）；fbustype 修正后的月度直缴 SQL |

### A6 参考模板 ⚠️ 未沉淀

| 项 | 说明 |
|---|---|
| **存什么** | 参数化 SQL 模板（Jinja2，带参数声明） |
| **怎么生成** | ◐ **半自动**：手写 YAML 模板 → `sync_reference_template_artifact_to_kb` 导入 |
| **作用** | `search_reference_template` / `execute_reference_template`：gen_sql 命中模板直接填参数执行，**比 few-shot 更强**（强制参数化口径） |
| **存储位置** | `…/datus_db/reference_template.lance`（本机未出现）+ 模板 YAML 源文件 |

### A7 平台文档 ✦ 按需引入

| 项 | 说明 |
|---|---|
| **存什么** | 数据库平台官方文档（ClickHouse/StarRocks…语法、函数、限制） |
| **怎么生成** | ◐ **业务引入**：`datus-agent platform-doc --platform <name>` 拉取官方文档建立索引 |
| **作用** | `list_document_nav` / `search_platform_doc`：写方言敏感 SQL 前验证函数用法（如 CH 23.3 的 dateTrunc 限制） |
| **存储位置** | `{datus_home}/data/{project}/document/{platform}/` |

### B2 原子知识文件 ⚠️ 未生成

### B4 语义模型源文件 ⭐ 已建（KB 的事实源）

| 项 | 说明 |

### B5 持久记忆 ⭐ 使用中

| 项 | 说明 |
|---|---|

## 三、生成方式速查表

| 资产 | 生成方式 | 触发命令/动作 | 本机状态 |
|---|---|---|---|
| A1 语义对象投影 | ✅ 自动 | semantic_modeling 收尾自动；或 `bootstrap-kb --components semantic_model --kb_update_strategy sync-yaml`（手改兜底） | ✅ 100 字段/9 关系 |
| A2 指标投影 | ✅ 自动 | 同上（与 A1 同一次同步，不可拆） | ✅ 16 指标 |
| A3 主题树 | ✅ 自动 | 随 A2 的 subject_path 自动建节点 | ✅ 6 节点 |
| A4 表结构元数据 | ✅ 自动 | `bootstrap-kb --components metadata`（增量可重跑） | ⚠️ 建模前旧数据，建议刷新 |
| A5 参考 SQL | ◐ 半自动 | `gen_sql_summary`（一条 SQL 一次） | ❌ 未沉淀 |
| A6 参考模板 | ◐ 半自动 | 手写模板 YAML + 导入 | ❌ 未沉淀 |
| A7 平台文档 | ◐ 业务引入 | `platform-doc --platform clickhouse` | ❌ 未导入 |
| B1 AGENTS.md | ◐ 半自动 | `/init` | ❌ 未生成 |
| B2 knowledge 文件 | ◐ 半自动 | `/init` 首建 + `extract-knowledge` 补充 | ❌ 未生成 |
| B3 台账/标准文档 | ✍️ 人工 | 建模/纠错后回填 | ⭐ 持续维护 |
| B4 语义 YAML | ✅ 自动 | semantic_modeling | ✅ fne_fund_main |
| B5 持久记忆 | ◐ 混合 | 会话沉淀+人工精炼 | ⭐ 使用中 |

**判定口诀**：
- **定义类知识**（表/字段/指标/关系是什么）→ 走建模，全自动；
- **示例类知识**（好 SQL 长什么样）→ 走沉淀/模板，半自动（每条人工触发）；
- **规则类知识**（为什么/禁止什么）→ 人工写文档 + /init 索引化，机器只做搬运；
- **环境类知识**（平台语法）→ 引入官方文档。

## 四、检索机制对照（谁在什么时候读什么）

| 问数阶段 | 读取的资产 | 闸门（不可用时工具不注入） |
|---|---|---|
| 理解问题 | B1（AGENTS.md 注入前 200 行）→ B3/B2 按索引精读 | AGENTS.md 不存在则跳过（无提示） |
| 找表 | A4 `search_table` / A1 `search_semantic_objects(kinds=["dataset","field"])` | `has_schema` / `has_semantic_objects` |
| 找口径 | A2 `search_metrics` + A3 `list_subject_tree`；B4 的 instructions 随 describe_table 注入 | `has_metrics` |
| 找教例 | A5 `search_reference_sql` / A6 `search_reference_template` | `has_reference_sql` / `has_reference_templates` |
| 验证方言 | A7 `search_platform_doc` | `has_indexed_docs` |
| 执行修正 | B5 记忆中的硬规则（如 fbustype='1'）随系统提示注入 | 记忆存在即注入 |

## 五、维护动作清单（按优先级）

1. **刷新 A4**：`bootstrap-kb --components metadata --kb_update_strategy incremental`（建模后表结构/采样未变，但清一次保险）；
2. **建 B1+B2**：跑 `/init`（用 01~07 文档作输入），生成 AGENTS.md + knowledge/*.md——**当前最大缺口**：B3 人工知识没有索引化通道，agent 只能"碰巧"读到；
3. **沉淀 A5**：把 fbustype 修正后的月度直缴 SQL 经 gen_sql_summary 沉淀（最有价值的一条：含 sumIf 口径+半开区间+反引号全部教训）；
4. **可选 A7**：`platform-doc --platform clickhouse`（CH 23.3 的方言坑已有本地闸门文档 08，优先级低）；
5. **每次建模后**：B3 台账回填（06/07）→ 自动带动 A1/A2/A3（无需手动）。
